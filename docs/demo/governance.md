# テストネット版ガバナンスデモ

この画面は、音楽クリエータ院議会とユーザ院議会が別々に投票し、両院承認後の同一実行マニフェストだけをタイムロック経由で実行する最小実装を検証します。

## 実装済みの境界

- 会期ごとに同量の投票クレジットを付与する
- 一人を同じ会期の両院へ重複登録しない
- 投票強度の二乗を消費し、票の差替えでは旧コストを返却する
- 両院の定足数と純額スコアを別々に確定する
- 内容、仕様、実行マニフェスト、対象、値、呼出しデータをハッシュで拘束する
- レビュー後に変更区分別のタイムロックを開始する
- 緊急時ガーディアンは待機中の操作を取り消せるが、別操作へ置換できない

## テストネットで簡略化している事項

- 議員は検証可能な抽選ではなく、テスト運営者が登録する
- 投票は公開トランザクションであり、コミット・リビールやゼロ知識証明を使わない
- レビューは証拠ハッシュの登録だけで、法務・監査の完了を保証しない
- P3憲章変更は直接投票の証拠ハッシュを要求するが、直接投票機構自体はまだ実装しない
- 実行対象は無価値のデモポリシーであり、実在JPYC、資金庫、本番SBTまたは本番アップグレード権限を操作しない
- 株主総会、取締役会、STO投資家の権利や株式会社の法的責任を代替しない

コントラクト仕様の基準は[ガバナンス変更プロトコル](/protocol/specs/governance-change)、制度全体は[二院制議会・ガバナンス](/governance/)を参照してください。
