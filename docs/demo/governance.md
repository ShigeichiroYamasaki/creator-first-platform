# テストネット版ガバナンスデモ

この画面は、音楽クリエータ院議会とユーザ院議会が別々に投票し、両院承認後の同一実行マニフェストだけをタイムロック経由で実行する最小実装を検証します。

## 実装済みの境界

- 会期ごとに同量の投票クレジットを付与する
- 一人を同じ会期の両院へ重複登録しない
- 投票強度の二乗を消費し、票の差替えでは旧コストを返却する
- 両院の定足数と純額スコアを別々に確定する
- 内容、仕様、実行マニフェスト、対象、値、呼出しデータをハッシュで拘束する
- レビュー後に変更区分別のタイムロックを開始する
- 緊急時ガーディアンは待機中の操作を取り消せるが、別操作へ置換できない
- 投票前に憲章適合性・法務実行可能性の証拠と両院それぞれの熟議記録を要求する
- CFP-0002では、両院承認・事後実装レビュー・P2タイムロックの完了後にだけ、固定saltのポリシーコントラクトを決定論的アドレスへデプロイする

## テストネットで簡略化している事項

- 議員は検証可能な抽選ではなく、テスト運営者が登録する
- 投票は公開トランザクションであり、コミット・リビールやゼロ知識証明を使わない
- レビューは証拠ハッシュの登録だけで、法務・監査の完了を保証しない
- P3憲章変更は直接投票の証拠ハッシュを要求するが、直接投票機構自体はまだ実装しない
- 実行対象は無価値のデモポリシーであり、実在JPYC、資金庫、本番SBTまたは本番アップグレード権限を操作しない
- 株主総会、取締役会、STO投資家の権利や株式会社の法的責任を代替しない

コントラクト仕様の基準は[ガバナンス変更プロトコル](/protocol/specs/governance-change)、制度全体は[二院制議会・ガバナンス](/governance/)を参照してください。

## CFP-0002のローカル検証シナリオ

[CFP-0002](/proposals/CFP-0002-early-supporter-one-year-rule)について、Hardhat自動テストは次の順序を検証します。

1. CFP本文、初期サポーター仕様、憲章適合性レビュー、法務レビューおよび各院熟議記録をハッシュ化する。
2. 適合性審査が不合格なら熟議完了と投票を拒否する。
3. 片方の院の熟議記録が欠ける場合も投票を拒否する。
4. 音楽クリエータ院議会とユーザ院議会のテスト議員が別々に投票し、各院の定足数と賛成スコアを確定する。
5. 両院承認後、対象ソース、コンパイル済み生成物、テストスイート、[試験報告](/proposals/reviews/CFP-0002-contract-test-evidence)および承認済みcalldataを同じ提案へ結合する。
6. テスト証跡が未登録、不合格または別calldataに対するものなら、実装・セキュリティレビューとキュー投入を拒否する。
7. 合格テスト証跡の登録後に実装・セキュリティレビュー証拠を登録し、P2タイムロックへ入れる。
8. タイムロック前、異なるcalldata、議会を経ない直接呼出しではデプロイできないことを確認する。
9. タイムロック後に承認済みファクトリーが予測済みアドレスへポリシーをデプロイし、365日の排他的上限を境界値で確認する。

実行コマンドは、Node.js 24環境で`npm run contracts:test`です。`CFP-0002 constitutional review, bicameral approval and governed deployment`の4試験が該当します。

この検証で用いる議員、レビューおよび熟議は合成されたテスト証拠であり、現実の議員による審議、弁護士の法律意見、三憲章の正式採択、独立監査またはSepoliaデプロイを意味しません。
